# 知識探索

一個單一 HTML 檔構成的個人知識學習網頁。每次隨機帶來一個學術知識點，可以沿著文中的專有名詞一路往下延伸，並把學過的內容長成一棵屬於自己的知識樹。

知識內容由 Google Gemini 撰寫，但**撰寫前一定先取得可信來源的原文**（英文維基百科或 OpenAlex 學術資料庫），模型的角色是「摘要與翻譯」，而不是「憑記憶創作」。整個專案不需要後端伺服器，可以免費部署在 GitHub Pages。

## 功能總覽

### 介面
- **導覽列**：上方以線條圖示切換四個頁面：指南針為「探索」、分支節點為「知識樹」、書籤為「收藏」、齒輪為「設定」。目前所在頁面以強調色標示，滑鼠停留或使用螢幕閱讀器時會顯示功能名稱。
- **底部按鈕列**（探索頁）：依序為「換一個」知識點、提問、收藏、存疑、笑臉、哭臉；除了「換一個」之外皆為線條圖示，啟用時圖示會填上淡色，並跳出文字提示。

### 探索
- **隨機知識點**：從設定的領域中隨機挑選子領域，依目前難度取得來源並產生一張知識卡片。
- **延伸名詞**：卡片內文中畫底線的專有名詞可以點擊，展開成一張新卡片；下方「延伸名詞」清單附有英文名稱與一句話說明。已展開過的名詞會直接讀取本機紀錄，不重複消耗額度。
- **探索路徑**：從名詞一路點下去時，上方會顯示來源脈絡（例如「阿羅不可能定理 › 無關選項獨立性 › …」），可以點回任何一層。
- **收藏**、**存疑**：按底部的書籤圖示收藏，收藏的卡片集中在「收藏」分頁；覺得內容可疑可按問號圖示標記「存疑」，卡片上會顯示提醒。
- **數學式排版**：支援 LaTeX，行內式 `$...$`、獨立式 `$$...$$`，由 MathJax 繪製。

### 分享卡片
- 有可信來源的卡片，在「資料來源」右側有分享圖示。按下後叫出系統分享選單，訊息為「卡片標題｜一句話摘要」加上連結；不支援的瀏覽器改為複製連結。
- 分享內容包含標題、內文、延伸名詞、來源、為何可信，以及難度、來源類型、撰寫模型與產生日期；收藏、存疑、笑臉哭臉等個人標記不會分享。
- 舊版本產生、沒有來源查證的卡片不提供分享，需先重新產生。
- 收到連結的人不需要金鑰或登入即可閱讀，畫面獨立於自己的探索進度；可選擇「加入我的知識樹」，加入的卡片標示「來自分享」。點延伸名詞時，有金鑰會先自動加入再展開，沒有金鑰則提示設定方式。

### 五級難度與回饋
- 難度分為**高中、大學部、碩士、博士、專家**五級，設定頁可選擇全域預設值。
- 底部按鈕列最右側有**笑臉**與**哭臉**：笑臉讓該**大領域**下次更難一級，哭臉更簡單一級；再按一次可取消，改按另一個會直接反轉。
- 難度同時決定**知識來源**（詳見下方「防止 AI 幻覺」）。

### 知識樹
- 以「知識」為圓心的放射狀地圖：16 個大領域永遠顯示，向外只長出**學過的子領域**，最外圈是看過的知識點與延伸名詞。地圖會隨著學習慢慢長出新的分支。
- 學過的分支以該領域顏色連線，尚未學過的大領域以灰色虛線顯示。
- 支援兩指縮放與拖曳。點大領域可看全部子領域的進度（未學過的標示「尚未探索」，也能從這裡開新的分支）與目前難度；點子領域可「在這個分支學一個新的」。
- 點卡片時，全文顯示在螢幕下半部，上方地圖仍可拖曳並直接點別的分支切換比對；選取的節點會加粗標示，被面板擋住時地圖會自動平移。按「在探索頁開啟」或點延伸名詞，才會切換到探索頁。
- **整理分支**：分類不吻合時，可在卡片面板按「移動」，選擇新的「大領域／子領域」，底下的延伸卡片會一起搬過去（原本接在其他卡片下的，會脫離上層成為獨立分支）。「刪除」會移除這張卡片與底下所有延伸卡片，刪除紀錄會隨 Google Drive 同步，其他裝置同步後也會一併刪除。

### 即時提問
- 按底部按鈕列的對話框圖示開啟提問面板，再按一次或按「關閉」收起；切換到其他頁面時會自動收起。
- 面板只占螢幕下半部，上方文章不會變暗，可以**邊捲動閱讀、邊連續追問**；文章底部會預留空間，不會被面板遮住。
- 正在閱讀卡片時，可勾選「附上目前的卡片作為背景」，針對該卡片追問推導、反例或應用。
- 提問內容只保存在記憶體中，關閉網頁即消失。

### 模型
- 可選擇 Gemini 3.5 Flash-Lite（預設）、3.8 Flash、3.7 Flash、3.6 Flash、3.5 Flash。
- 設定頁內有可展開的免費額度說明（RPM、TPM、RPD）。
- **自動重試與備援**：伺服器忙碌（5xx）時自動等待 2 秒、5 秒各重試一次；仍失敗或額度用完（429）時，依序改用其他模型，並在卡片上標示實際撰寫的模型。

### 外觀
- 設定頁「外觀」可選擇淺色（太陽）、深色（月亮）或跟隨系統，頁面載入前就套用，不會閃爍。

### 同步與備份
- **Google Drive 同步**：備份存在使用者自己 Drive 的隱藏應用程式資料夾。同步採雙向合併，手機與電腦各自學的卡片都會保留；同一張卡片兩邊都有修改時，以較新的為準；任一方刪除的卡片，合併後都不會再出現。
- 登入有效期間，變更會在 15 秒後或切換到其他 App 時自動上傳；超過一天未同步會在探索頁提醒。
- **手動匯出／匯入**：匯出成 JSON 檔，匯入時與現有資料合併，不會覆蓋。
- 支援以 Safari「加入主畫面」，以接近 App 的方式全螢幕使用。

## 防止 AI 幻覺的技術細節

AI 模型最主要的風險，是在缺乏依據時「自信地編造」事實、人名、數據或參考文獻。本專案的核心設計是：**讓模型只負責理解與轉述有出處的原文，而不是負責記得知識。**

### 1. 依難度分級的可信來源

| 難度 | 來源 | 選取方式 | 撰寫模型 |
|---|---|---|---|
| 高中、大學部 | 英文維基百科 | 以子領域英文名稱搜尋，優先選取維基百科評定的「典範條目」與「優良條目」；排除列表、大綱、索引類頁面 | 設定頁所選模型 |
| 碩士 | OpenAlex 學術資料庫 | 被引用超過 200 次、具公開摘要的期刊論文或綜述，依被引用次數排序；再以期刊「兩年平均被引次數」篩除後半段期刊 | 設定頁所選模型 |
| 博士、專家 | OpenAlex 學術資料庫 | 近三年發表、被引用超過 9 次、具公開摘要的期刊論文或綜述，同樣篩選期刊 | 僅限 3.8 Flash 或 3.7 Flash |

- 期刊影響係數（Impact Factor）屬於 Clarivate 的付費資料，無法免費取得；OpenAlex 的「兩年平均被引次數」計算方式與 IF 相近，作為免費替代指標。
- OpenAlex 的搜尋排除了預印本（preprint），只保留期刊論文與綜述。
- 從卡片延伸出的名詞，也沿用同一級的來源規則：在維基百科或 OpenAlex 查詢該名詞的英文名稱。

### 2. 以原文約束模型

送給 Gemini 的指示中，原文會被明確標示起訖，並附上以下規則：

- **維基百科來源**：只能根據原文撰寫；原文沒有提到的事實、數字、人名、年份一律不得加入；資訊不足時寧可略過，也不得以自身知識補上。
- **論文來源**：關於論文本身的敘述必須以摘要為依據，不得杜撰摘要中沒有的實驗結果、數據或結論；只能補充教科書層級的背景知識，且不得引用其他特定論文的細節。
- **近三年論文**：必須清楚區分「這篇論文的主張」與「學界已確立的背景知識」，並說明證據程度（例如單一研究、尚待重複驗證）。
- 產生卡片時的 temperature 設為 0.4，降低隨機發揮的程度。
- 模型以 JSON 結構化格式回傳，網頁會檢查必要欄位，格式不完整即視為失敗，不會顯示半成品。

### 3. 參考文獻由程式附上，而非由模型撰寫

- 模型被要求回傳空的參考文獻欄位，卡片底部的「資料來源」**一律由程式根據實際取得的來源附上**：維基百科條目網址，或論文的 DOI 連結、作者、年份、期刊與被引用次數。
- 因此參考文獻不可能是模型編造的，點擊即可另開新頁閱讀原文。
- 舊版本產生、沒有來源紀錄的卡片，參考文獻會改以「精確標題」連到 Google Scholar 搜尋，避免連到模型可能編造的網址或 DOI。

### 4. 查無來源時寧可不寫

- 隨機挑選時若找不到合適的條目或論文，會提示換個領域，而不是退回讓模型憑記憶撰寫。
- 延伸名詞在來源中查不到時，會明確告知「為了確保內容來自可信來源，這個名詞暫時無法展開」。
- 博士以上若 3.8 Flash 與 3.7 Flash 都無法使用，會直接回報錯誤，**絕不降級**到能力較弱的模型。

### 5. 讓使用者看得見依據

- 卡片上方標示來源類型（依據英文維基百科、依據高被引代表論文、依據近三年論文）、產生時的難度，以及在備援或博士以上時實際撰寫的模型。
- 「為何可信」說明支持這項知識的依據；新論文卡片則改為「證據程度」。
- 「存疑」標記讓使用者記錄可疑內容，並會隨同步保存。

### 6. 分類校正

- 系統指示中會列出網頁支援的全部「主領域／子領域」清單，要求模型只能從清單中挑選分類。
- 隨機抽卡時，程式已先決定好分類，並在指示中要求模型照抄「主領域／子領域」，不得自行變更或發明。
- 模型回傳後，程式會檢查分類是否存在於清單中；不符時以程式決定的分類覆蓋，並提示「分類已校正」。
- 知識樹上的位置一律由程式抽到的分類決定，不受模型回傳內容影響；若仍覺得不吻合，可在知識樹上手動移動。

### 7. 分享內容的防護

- 分享連結的內容可以被任何人修改，網頁無法證明未被竄改，因此分享頁面固定顯示「這是他人分享的內容，本網站無法保證未被修改，請以來源原文為準」。
- 分享內容一律視為不可信輸入：每個欄位都經過型別檢查與長度限制，所有文字都以純文字顯示，無法夾帶程式碼。
- 只有維基百科、doi.org、OpenAlex 網域的 https 網址會顯示為連結，其他網址一律以純文字呈現，避免被導向假冒的來源。
- 沒有可信來源的卡片不能分享，避免未經查證的內容擴散。

### 已知限制

以上機制能大幅降低幻覺，但無法保證百分之百正確：

- 維基百科本身可能有錯誤或過時內容，即使是典範與優良條目也一樣。
- 多數論文僅公開摘要，碩士以上的卡片深度受摘要長度限制；模型仍可能誤讀或過度簡化原文。
- 高被引不等於正確，近三年的論文尤其可能在日後被修正或推翻。
- 以子領域名稱搜尋，偶爾會挑到與該領域只有間接關聯的條目或論文；分類校正只確保標示一致，無法判斷內容本身是否真的屬於該子領域。
- 即時提問沒有來源約束，屬於模型的一般回答，重要內容請自行查證。

## 隱私說明

本專案**沒有任何後端伺服器**，開發者無法看到任何使用者的資料。所有資料只存在以下位置：

### 存在使用者自己的瀏覽器
- 卡片、知識樹、收藏、存疑、難度調整、設定，以及 Gemini API 金鑰，都存在瀏覽器的 localStorage，綁定「這個瀏覽器 + 這個網址」。
- 關閉網頁後仍會保留；使用無痕模式、清除網站資料，或 iOS 長期未使用時可能被清除。
- 設定頁「清除所有卡片」只會清除本機資料。

### 存在使用者自己的 Google Drive（啟用同步時）
- 備份檔寫入 Drive 的**隱藏應用程式資料夾**，不會出現在檔案列表，也只有本網頁讀得到。
- 網頁申請的權限範圍只有 `drive.appdata`，**無法讀取使用者 Drive 中的任何其他檔案**。
- 同步內容包含學習資料與 Gemini API 金鑰，讓新裝置登入後自動取回；手動匯出的備份檔則**刻意不含金鑰**，避免檔案外流時連帶洩漏。
- Google 登入憑證只保存在記憶體中，約一小時後失效，不會寫入儲存空間。
- 可隨時在設定頁「中斷連結」，或到 Google 帳戶的「第三方應用程式存取權」撤銷授權。

### 分享連結
- 卡片內容壓縮後放在網址 `#` 之後。這部分不會傳送到 GitHub 或任何伺服器，只有拿到連結的人看得到。
- **連結本身就包含卡片全文**：任何拿到連結的人都能閱讀，傳出後無法撤回或刪除。分享內容不含任何個人標記或帳號資訊。
- 連結長度約數百到數千個字元，在部分 Email 或舊系統中可能被截斷而無法開啟。

### 會傳送到外部服務的資料

| 服務 | 傳送內容 | 用途 |
|---|---|---|
| Google Gemini API | 系統指示、來源原文、難度；延伸名詞與提問時包含上一張卡片的內容；提問時包含對話紀錄 | 撰寫卡片、回答提問 |
| 英文維基百科 | 子領域或名詞的英文名稱 | 搜尋與讀取條目 |
| OpenAlex | 子領域或名詞的英文名稱、期刊 ID；以及一個通用的識別信箱（非使用者個人資料） | 搜尋論文與期刊指標 |
| Google Drive／Google 登入 | 備份檔、授權請求 | 同步 |
| cdnjs、Google Fonts、GitHub Pages | 一般網頁請求（會包含 IP 位址等連線資訊） | 載入程式庫、字型與網頁本身 |

- **請特別注意**：Gemini API 免費方案的輸入內容，可能被 Google 用於改善其產品與模型。請勿在提問中輸入個人隱私或機密資訊。
- 網頁原始碼中**不含任何金鑰**。內建的 OAuth 用戶端 ID 屬於公開識別碼，不是密碼。
- 網頁不使用任何分析、追蹤或廣告程式。

## 部署方式

### 1. 架設網頁（GitHub Pages）
1. 建立一個公開的 GitHub repository，上傳 `index.html`（檔名必須是 `index.html`）。
2. 進入 repository 的 **Settings → Pages**，Source 選「Deploy from a branch」，Branch 選 `main`、資料夾選 `/(root)`，按 Save。
3. 一到兩分鐘後會得到網址，例如 `https://帳號.github.io/knowledge/`。

### 2. 設定 Gemini API 金鑰
到 [Google AI Studio](https://aistudio.google.com/apikey) 建立免費金鑰，貼到網頁「設定」頁。

### 3. 設定 Google Drive 同步（選用）
1. 在 [Google Cloud Console](https://console.cloud.google.com/) 建立專案並**啟用 Google Drive API**。
2. 設定 OAuth 同意畫面（Google Auth Platform）：使用者類型選「外部」，維持「測試」狀態，並在「測試使用者」加入要使用的 Gmail（上限 100 人）。
3. 建立「網頁應用程式」類型的 OAuth 用戶端，在「已授權的 JavaScript 來源」填入 `https://帳號.github.io`（只填網域，不加路徑與結尾斜線）。
4. 將用戶端 ID 填入網頁設定頁，或寫入 `index.html` 中的 `DEFAULT_CLIENT_ID`。

### 分享給朋友
朋友使用同一個網址即可，不需另外建立專案；只要把對方的 Gmail 加入測試使用者。每個人使用自己的 Gemini 金鑰，資料存在各自的 Google Drive，彼此看不到對方的資料。

## 技術架構

- **單一 HTML 檔**：介面、樣式與程式邏輯全部寫在 `index.html`，無建置流程。
- **外部程式庫**（皆由 CDN 載入）：D3.js 7.9.0（知識樹地圖）、MathJax 3.2.2（數學式）、Google Identity Services（Drive 授權）。
- **外部 API**：Gemini API（`generativelanguage.googleapis.com`）、MediaWiki Action API（`en.wikipedia.org/w/api.php`）、OpenAlex（`api.openalex.org`）、Google Drive API v3。
- **本機儲存**：localStorage，鍵名以 `kx_` 開頭；完整卡片上限 400 張，超過時最舊的卡片只清除內文、保留在知識樹中，可重新產生。
